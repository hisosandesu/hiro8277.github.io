# /learn - 再利用可能なパターンを抽出

現在のセッションを分析し、スキルとして保存する価値のあるパターンを抽出します。

## トリガー

セッション中に非自明な問題を解決したときに`/learn`を実行します。

## 抽出対象

以下を探す：

1. **エラー解決パターン**
   - どのようなエラーが発生したか？
   - 根本原因は何だったか？
   - 何が修正したか？
   - 類似のエラーに再利用可能か？

2. **デバッグテクニック**
   - 明らかでないデバッグステップ
   - 機能したツールの組み合わせ
   - 診断パターン

3. **回避策**
   - ライブラリの癖
   - APIの制限
   - バージョン固有の修正

4. **プロジェクト固有のパターン**
   - 発見されたコードベースの規約
   - 行われたアーキテクチャ決定
   - 統合パターン

## 出力フォーマット

`~/.claude/skills/learned/[pattern-name].md`にスキルファイルを作成：

```markdown
# [説明的なパターン名]

**抽出日:** [日付]
**コンテキスト:** [これが適用される状況の簡単な説明]

## 問題
[これが解決する問題 - 具体的に]

## 解決策
[パターン/テクニック/回避策]

## 例
[該当する場合はコード例]

## 使用タイミング
[トリガー条件 - このスキルをアクティブにするべきもの]
```

## プロセス

1. 抽出可能なパターンがないかセッションをレビュー
2. 最も価値のある/再利用可能な洞察を特定
3. スキルファイルをドラフト
4. 保存前にユーザーに確認を求める
5. `~/.claude/skills/learned/`に保存

## 注意

- 些細な修正は抽出しない（タイポ、単純な構文エラー）
- 一度きりの問題は抽出しない（特定のAPI障害など）
- 将来のセッションで時間を節約するパターンに焦点を当てる
- スキルは焦点を絞る - 1スキルに1パターン
