# receiptParser.js 設計原則

`reconstructTextSpatially` の出力は「2スペース区切り」（左列=品目、右列=価格）。
`ITEM_SIMPLE` の `\s{2,}` はこれを前提とする。`TOTAL_RE` を EXCLUDE チェックより前に評価する（合計行と電子マネー行がマージされた場合の対応）。

## 日付抽出（2026-04-07 更新）4パターン対応

- `YYYY/MM/DD` / `YYYY年M月D日`（既存）
- `YYYY.MM.DD`（ドット区切り）
- `令和N年M月D日`（令和表記。`reiwaToWestern(n) = 2018 + n`）
- `R\d{1,2}[./]\d+[./]\d+`（R8.4.7 / R8/4/7 短縮形）

## 値引き・数量パターン（2026-04-07）

- 値引きキーワード `値引き|割引|クーポン` を含む品目行はマイナス金額として扱う（`-Math.abs(price)`）
- `QTY_LINE` が `単価?|@` プレフィックスと全角 `×` に対応

## extractTotal 改善履歴

**Pattern 3（2026-04-09）**: greedy `[^]*` 方式を廃止。
- 旧: `"Edy支払計　¥14,151"` → greedy が「計　¥14,15」を先食いして `1` だけキャプチャ
- 新: `PAYMENT_TOTAL_KW_RE` で対象行を絞り、行内の全価格候補を収集して末尾値を採用
- `¥→4` ML Kit 誤認識（ML Kit が ¥ を 4 と読む）に `[¥￥4]?` で対応

**税合計マージ行対応（2026-04-11）**:
- 問題: `(税合計 ¥1,071)` と `合計 ¥14,151` が同一Yグループにマージされると total=1071 の誤取得
- 対策: TOTAL_RE マッチ行に `税合計` を含む場合、行内全価格候補の最大値を返す

```javascript
if (/税合計/.test(trimmed)) {
  return Math.max(...candidates);
}
```

## extractMerchant 除外パターン（2026-04-11）

実機OCRで判明した3種の誤判定:
- `※印は軽減税率...` — `※`(U+203B) が `[＊*]` に未対応 → `[＊*※]` に拡張
- PLUコード行 (`0342*塩あじ枝豆...`) — `/^[A-Z]?\d{3,4}[＊*\s]/` を EXCLUDE に追加
- 価格のみ行 (`Y598`) — `/^[¥￥Yy+]?\d{3,}$/` を EXCLUDE に追加

## PRICE_PREFIX Y/y 対応（2026-04-11）

実機OCRで `Y275`/`y498` (Y→¥ のラテン大文字誤認識) が確認された。

```
PRICE_PREFIX = '(?:[¥￥+Yy]|4(?=\\d{3}\\s*$))?'  // Yy を追加
ITEM_TRAILING_PRICE も [¥￥+Yy] に拡張
```
